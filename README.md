# نموذج قسم التدريب — معهد الدراسات القضائية والقانونية

نموذج عربي تفاعلي مبني على متطلبات قسم التدريب والتصور الوظيفي الذي تمت مراجعته في المحادثة. جميع الملفات في مجلد واحد، وصفحة الدخول هي **index.html**. لا يحتاج إلى تثبيت أو بناء.

## التشغيل

- افتح `index.html` مباشرة في متصفح حديث.
- أو شغّل `node serve.cjs` ثم افتح `http://127.0.0.1:8080`.
- تعمل الخطوط والأيقونات والبيانات محليًا؛ لا يعتمد الموقع على CDN أو اتصال خارجي.
- عند التشغيل من GitHub Pages تُحفظ التعديلات في المتصفح الذي تستخدمه. لا تتشارك الأجهزة أو المستخدمون قاعدة بيانات.

## رفع النموذج إلى GitHub Pages

1. فك ضغط الملف المرفق.
2. ارفع **محتويات المجلد** إلى جذر المستودع، بحيث يظهر `index.html` مباشرة بجانب ملفات JavaScript وCSS والخطوط. لا ترفع ZIP وحده.
3. افتح المستودع: **Settings → Pages**.
4. ضمن **Build and deployment** اختر **Deploy from a branch**.
5. اختر الفرع **main** والمجلد **/(root)** ثم **Save**.
6. افتح رابط الموقع الذي يعرضه GitHub بعد اكتمال النشر.

الروابط تستخدم `#`، ولذلك تعمل عند التحديث ومن مسار مستودع فرعي دون إعداد إعادة توجيه. ملف `.nojekyll` مرفق.

المراجع الرسمية:
- https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site
- https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## رحلة مقترحة للمراجعة

1. من البرامج: أضف برنامجًا → أرسل للاعتماد → سجّل قرار الاعتماد.
2. من ملف البرنامج: جدول فعالية → اختر المنسق → افتح التسجيل.
3. من التسجيل أو دليل الدورات: سجّل متدربًا. اختبر رسومًا بقيمة أكبر من صفر لتجربة الدفع.
4. من تفاصيل الطلب: جرّب فشل السداد ثم نجاحه. المبالغ للعرض فقط، دون بوابة دفع أو بيانات بطاقة.
5. من الحضور والتنفيذ: سجل حضور الجلسات → أرفق كشف PDF تجريبي → أدخل الساعات الفعلية → أرسل للمراجعة.
6. بدور رئيس القسم: اعتمد التنفيذ.
7. من الشهادات: أصدر شهادة للمستحق واعرضها أو احفظها PDF عبر الطباعة.
8. من الحسابات: استخرج استحقاق المدرب ثم سجل الصرف التجريبي.
9. راجع أثر التغييرات في التقارير وسجل الإشعارات.

## ما هو مستخلص وما هو مقترح؟

**من المرفقات:** فصل البرنامج عن الفعالية، الاعتمادات، الجدولة وإسناد مهمة للمنسق، بيانات ما بعد التنفيذ، سجل المدربين، التقييم والتقارير.

**إضافات مقترحة:** الدليل العام، حسابات المستفيدين، التسجيل الذاتي، السداد والاسترداد الإلكتروني، التحقق من الشهادة والدعم.

النسخة الأصلية للمرفقات مسودة للمراجعة. النموذج يوضح رحلة الاستخدام، ولا يعد اعتمادًا للسياسات أو بديلًا عن مواصفات التنفيذ النهائية. رمز الميزان والهوية البصرية في هذا النموذج تصميم توضيحي.

## افتراضات العرض وحدوده

- سيناريو العرض مؤرخ في نوفمبر 2026؛ مرجع لوحة التأخير والتقويم هو 11 نوفمبر 2026. الأحداث الجديدة تسجل وقت التعديل الفعلي.
- سياسة الحضور 80% والنجاح 60% افتراضان للعرض فقط ويمكن تعديلهما من الإعدادات؛ لم تُعتمدا كسياسة للمعهد. الاختبار اختياري لكل فعالية.
- أسعار الدورات وأسماء الأشخاص والجهات افتراضية. تستخدم ملفات المتدربين أرقامًا تبدأ بـ DEMO بدل أرقام هوية حقيقية.
- سجلات PDF المسماة في البيانات الأولية مجرد أمثلة؛ يمكنك رفع ملف تجريبي من جهازك عند تجربة التنفيذ.
- رفع المواد يعمل محليًا للصيغ PDF وWord وPowerPoint، بحد 500 كيلوبايت لكل ملف. كشف الحضور PDF.
- يمكن إرفاق مواد فعلية صغيرة واستعادتها في المتصفح نفسه. لا يُنصح بإدخال بيانات شخصية أو مالية حقيقية.
- لا توجد قاعدة بيانات مشتركة، أو مصادقة فعلية، أو صلاحيات على خادم، أو إرسال بريد فعلي، أو مدفوعات حقيقية.
- منع تعارض المكان يطبق على القاعة نفسها وحساب Zoom نفسه، وليس TEAMS أو الأماكن الخارجية.
- اختيار المنسق ينشئ مهمة؛ تغييره ينقل المهمة نفسها. حفظ الجدولة دون منسق مسموح، لكن نشرها في هذا السيناريو يتطلب منسقًا.
- المقاعد المدفوعة المعلقة تظل محجوزة حتى السداد أو الإلغاء يدويًا. انتهاء الحجز تلقائيًا والسياسات الزمنية والاسترداد التلقائي وظائف للنظام النهائي.
- لكل تقديم تاريخ رئيسي وعدد جلسات للحضور. تحديد موعد مستقل لكل جلسة من جلسات برنامج متعدد الأيام يحتاج توسيع نموذج الجدولة النهائي.
- التقييم يدعم 19 سؤالًا مباشرًا. استيراد Excel/Microsoft Forms والتكامل مع المنصات والجهات المالية خارج نطاق النسخة الثابتة.
- تصدير التقارير CSV بترميز UTF-8 يفتح في Excel. ملف PDF ينتج من أمر الطباعة واختيار Save as PDF، وليس ملف Excel بصيغة XLSX.
- التحقق من الشهادة محلي داخل بيانات المتصفح نفسه، وليس خدمة عامة للتحقق. جميع الشهادات والإيصالات موسومة بأنها تجريبية.
- لا تغير السياسة الجديدة الشهادات السابقة تلقائيًا؛ يمكن إلغاؤها يدويًا مع السبب.
- استخراج المكافأة يحفظ أجر الساعة والساعات في سجل مستقل. أجر 8 نقاط قرار مفتوح؛ نموذج إضافة المدرب يقبل النقاط 1–7.
- الاحتفاظ بالمهام المكتملة وفصل انتظار الاعتماد عن التأخير مقترحان للعرض.
- في النظام الفعلي يلزم استكمال بيانات المصدر المشروطة، قوائم البرامج الرسمية، الاعتمادات والمرفقات، الترشيحات الجماعية، سياسات الرسوم، وجدول الصلاحيات التفصيلي.
- المرفقات تشير إلى Oracle APEX للتنفيذ الفعلي. هذا نموذج مستقل HTML/CSS/JavaScript لعرض التصميم والمسارات على GitHub Pages.

## الملفات

- `index.html`: صفحة الدخول الوحيدة.
- `styles.css`: الواجهة والتجاوب والطباعة.
- `model.js`: قواعد التداخل والمقاعد والاستحقاق والتصدير.
- `data.js`: بيانات عرض افتراضية.
- `app.js`: التنقل والقوالب العامة والحفظ المحلي.
- `views.js`: شاشات العرض.
- `actions.js`: إجراءات المستخدم والنماذج.
- `favicon.svg` وخطا Tajawal والترخيص: موارد محلية.
- `model.test.cjs`: اختبارات القواعد؛ شغل `node --test model.test.cjs`.
- `serve.cjs`: خادم معاينة محلي اختياري.
- `browser.test.cjs`: اختبار المتصفح باستخدام Playwright اختياري.
- `QA.md`: نتائج التحقق وحدوده.

من الإعدادات يمكنك تنزيل نسخة JSON من البيانات أو إعادة ضبط هذا النموذج وحده. لا توجد استعادة من ملف JSON في هذه النسخة.

## معلومات للمطور

لا توجد تبعيات وقت التشغيل أو خدمات خارجية أو مفاتيح API. تستخدم النوافذ عنصر dialog الأصلي، والمدخلات النصية تُرمز قبل إدراجها في HTML، وتُحيّد الصيغ عند تصدير CSV. التحقق من الصلاحيات في JavaScript لا يمثل حماية فعلية؛ كل بيانات العرض عامة لمن يفتح الصفحة.

مرجع dialog المستخدم أثناء التنفيذ: https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog

لتشغيل اختبار المتصفح اختياريًا: وفر حزمة Playwright مع Microsoft Edge، شغّل المعاينة على المنفذ 8766، ثم `node browser.test.cjs`. لا تحتاج هذه الأدوات لتشغيل الموقع نفسه.
